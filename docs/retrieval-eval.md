# 检索质量评估

> 可复现：`npm run eval:retrieval`（合成语料，不联网、不花钱）。
> CI 每次跑并设 100% hit@5 门槛，防止检索质量回归。

## 语料与方法

- 120 章中文小说（约 15 万字），随机生成对话/场景，再**植入 6 个可唯一判定的事实**：
  - 第 17 章：林牧在雾海渡口救下苏晚
  - 第 43 章：阿九在听潮阁交出渡籍
  - 第 68 章：苏晚替林牧挡下镇渊司的封条
  - 第 91 章：铜哨在旧码头被找到
  - 第 104 章：青袍人烧掉旧信
  - 第 119 章：林牧在听潮阁见到父亲的船
- 查询覆盖 10 类：事件、物品、实体、短语、共现、自然语言、同义改写（"谁救了苏晚" vs 原文"救下苏晚"）；
- 指标：hit@1 / hit@5 / MRR（正确答案章节是否出现在返回片段的对应位置）。

## 结果（v0.25.0 基准）

| 指标 | 结果 |
|---|---|
| hit@1 | **10/10** |
| hit@5 | **10/10** |
| MRR | **1.00** |
| 建索引 | 85 ms |
| 平均查询 | 5.9 ms |
| 索引体积 | 0.54 MB |
| 语料 | 120 章 / 约 15 万字 |

细节：`npm run eval:retrieval` 输出每条查询的命中位置。

## 设计说明

- 中文 1/2-gram + BM25：实体名、短语、自然语言都能命中，不需要分词器与 embedding；
- 查询里的中文二元组做二次过滤，压掉 1-gram 的单字误命中；
- 同义改写靠 1-gram 兜底（"救" 字共享），"谁救了苏晚" 仍能命中 "救下苏晚"。

## 局限

- 这是**合成语料**，不是真实书稿；真实网文的同名人物、代词指代、跨章伏笔会更难，
  因此 100% 不代表真实书稿 100%；`docs/performance.md` 里有 1000 章性能数据；
- 需要语义推理的查询（"谁背叛了主角" 这类没有关键词重合的问题）仍要靠 PageIndex 式
  章节树 + Agent 推理，而不是纯词汇检索；
- 后续可加入真实书稿评估集（需作者授权），并按卷限制检索范围以控制延迟。
