# 知识库初始化管线

> 解决的问题：导入一本 100 章的书之后，`world_model.md` / `summary.md` / `chapter_outline.md`
> 还是空模板，Agent 续写时"没有依据"。这条管线把已有章节蒸馏成知识文件。

## 1. 触发方式

工作台顶栏 **「初始化知识」** → 确认弹窗（显示章节数、字数、预计调用块数）→ 开始。
运行期间有进度弹窗（阶段 / 进度条 / 当前块 / 取消）。完成后生成 **一个** `[知识] 初始化` 提交。

## 2. 管线结构

```text
读取 chapters/*.md
  → 分块（按字符预算 12,000 字，章节不拆开；单章最多取 8,000 字）
  → 每块调用一次模型，产出：摘要 / 设定 / 状态 / 逐章一句话
  → 三次合并调用：剧情总纲、世界模型、状态卡
  → 逐章大纲由分块结果直接拼装（不再额外调用）
  → 写 summary.md / world_model.md / status_card.md / chapter_outline.md
  → 一次提交
```

对 100 章（约 30 万字）的典型成本：约 25 次分块调用 + 3 次合并调用，用 `deepseek-flash` 为几美分级；
单章/会话预算不参与这条管线（它是一次性初始化，不写入 Agent 会话成本）。

## 3. 提示词与产出约束

- 分块提示要求固定四节输出（摘要 / 设定 / 状态 / 逐章），逐章行格式固定为
  `- 0001 章节标题：一句话`，由本地正则解析，不依赖模型输出 JSON。
- 合并提示要求「只使用要点里的信息，信息不足写待补充」，避免编造世界观。
- 每个文件都有长度上限（总纲 1200 字 / 世界模型 1500 字 / 状态卡 800 字）。

## 4. 上限与安全

- 单次最多处理 **240 章**（`maxChapters`），超出部分在报告里标记 `skippedChapters`。
- 可随时取消：Host 在每次模型调用后检查取消标记。
- 失败不会写半成品：只有全部合并完成才落盘 + 提交。

## 5. 代码位置

| 文件 | 作用 |
|---|---|
| `src/pipeline/knowledge.ts` | 分块、提示词、解析、写盘、提交（`complete` 可注入，便于测试） |
| `src/pipeline/host.ts` | utilityProcess 入口：创建模型、调用 `completeSimple`、上报进度/成本 |
| `src/main/pipeline-manager.ts` | 进程生命周期与取消 |
| `tests/pipeline.test.ts` | 5 个用例：分块、逐章解析、完整流程（fake 模型）、上限、空书 |
| `scripts/e2e-knowledge.mjs` | 真实模型端到端：导入 4 章 → 初始化 → 校验四个文件 |

## 6. 后续可做

- 文风档案初始化（`style_guide.md` / `style_fingerprint.md`）纳入同一管线；
- 增量更新：只蒸馏新增章节，而不是整本重跑；
- 成本预估与预算闸门（目前只显示块数，不预估金额）。
